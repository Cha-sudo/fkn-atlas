# ФКН Атлас — проверяемый пилот 0.2.0

Результат стартовых итераций 0 и 1 по ТЗ из Wiki_FKN_Codex_Handoff_v5. Python 3.11+, стандартная библиотека, SQLite; установка моделей и сторонних пакетов не нужна.

**Фактический результат 13.11.2026:** офлайн-конвейер работает; главная и архив Wiki отвечают HTTP 502. В `runtime/pilot.sqlite` сохранены реальные ошибки, история повторов и контрольные метаданные Яндекс Диска. Полный каталог программ, загрузка учебных файлов и реконструкция курсов ещё не выполнены. Подробности: [STATUS](docs/STATUS.md), [исследование источников](docs/research/SOURCE_SURVEY.md).

## Запуск из распакованной папки

Распакуйте в новую папку, чтобы сохранить прежнюю версию. Команды выполняются из корня проекта.

Windows PowerShell:

```powershell
py -3 -m unittest discover -s tests -v
$env:PYTHONPATH="src"
py -3 -m fkn_atlas demo
py -3 -m fkn_atlas report --db runtime/demo.sqlite
py -3 -m fkn_atlas report --db runtime/pilot.sqlite
```

Linux/macOS:

```sh
python -m unittest discover -s tests -v
export PYTHONPATH=src
python -m fkn_atlas demo
python -m fkn_atlas report --db runtime/demo.sqlite
python -m fkn_atlas report --db runtime/pilot.sqlite
```

В среде разработки проверены Python 3.12.14 и Linux. Нативный запуск на Windows в этой сессии не проверялся. Команда `demo` работает из исходного дерева с каталогом `fixtures/`; отдельная wheel-установка не является проверенным способом доставки демонстрации.

## Ограниченный сетевой запуск

```sh
python -m fkn_atlas scout --db runtime/pilot.sqlite --max-pages 8 --delay 1.5
python -m fkn_atlas export --db runtime/pilot.sqlite --output runtime/pilot.jsonl
```

В PowerShell используйте `py -3` вместо `python`, если так установлен интерпретатор. Заданный `PYTHONPATH` нужен для всех команд модуля.

- Область обхода: только учебные HTML-адреса `fruitdet.ru/wiki`; внешние ссылки фиксируются с контекстом, автоматически не обходятся.
- Максимум 12 заданий за запуск; по умолчанию 8, глубина 2, интервал 1,5 с. Учитываются robots, Crawl-delay и Retry-After.
- Повторный запуск продолжает очередь. Ошибки откладываются с backoff; максимум 3 попытки задания, затем явное состояние `exhausted`. Успешно законченные страницы автоматически заново не скачиваются. Общая система периодического обновления ещё не реализована.
- `demo` и `scout` используют разные БД по умолчанию; смешивание режимов отклоняется. Для новой чистой выборки можно указать другое имя БД, сохранив предыдущую.
- При HTTP-ошибках команда формирует отчёт и сохраняет доказательства; код выхода 0 означает успешное выполнение процедуры, а не доступность сайта. Смотрите `pages_by_state`, `run_status`, очередь и события.
- `report` и `export` требуют существующую БД. Старый формат автоматически мигрируется без выдуманных снимков; legacy-вхождения явно отмечены. Перед открытием собственной БД старого формата сохраните резервную копию.

## Доказательства и результаты в комплекте

- `runtime/demo.sqlite`, `runtime/demo.blobs/`: 3 вымышленные страницы, 6 вхождений ссылок, 5 уникальных целей.
- `runtime/pilot.sqlite`, `runtime/pilot.blobs/`: реальные сетевые попытки и импортированные наблюдения; 0 полученных содержательных Wiki-страниц.
- `runtime/pilot.jsonl`: переносимый экспорт таблиц с ID и связями.
- `runtime/*report.json`, `runtime/*.log`: фактические отчёты и команды проверки; сообщения URL в `tests.log` относятся к моделированным ответам тестов.
- `runtime/research/`: исходные ответы диагностических запросов; контрольный Яндекс API содержит только метаданные 10 папок верхнего уровня.
- `scripts/import_survey.py`: офлайн-импорт исследовательских ответов с проверкой SHA-256 и идемпотентностью. Он не заменяет адаптер Яндекс Диска.
- `docs/HANDOFF_*`: исходные README и манифест передачи; исторические документы сохранены.

Храните БД вместе с одноимённой папкой `.blobs`: там находятся исходные байты. В снимках сохраняется оригинальный HTML, а в каталоге — только допустимые URL; неизвестные подписанные ссылки не попадают в очередь и структурированные журналы. Оригиналы являются локальными доказательствами и не предназначены для автоматической публикации.

## Что реализовано

Постраничная транзакция; атомарная запись оригиналов по SHA-256; история событий и версий; отдельное вхождение каждой ссылки по снимку и порядковому номеру; иерархия заголовков, контекст таблиц/списков; база относительных ссылок после редиректа; сохраняемые причины исключения; восстановление после остановки; миграция SQLite; JSONL-экспорт.

Пилот рассчитан на **одного worker** и обычную файловую систему с поддержкой hard links для атомарной публикации blob. Конкурентный запуск нескольких scout над одной БД не поддерживается. Байтовые лимиты действуют на ответ; общей дисковой квоты пока нет.

2. Реализовать отдельный адаптер Яндекс Диска: пагинация, вложенные пути, связи папка→объект, checkpoint и раздельные фазы metadata/content, используя сохранённый реальный ответ и моделированные случаи ошибок.
