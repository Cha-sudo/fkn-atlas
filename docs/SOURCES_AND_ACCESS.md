# Источники, охват и рабочая политика доступа

## 1. Образовательная область
Точки входа: главная Wiki и архив (`PROJECT_BRIEF.md`). На главной странице 13.11.2026 наблюдались в навигации ПМИ, ПИ, ПАД, КНАД, ЭАД, ДРИП, РИЦП, ПИРС, майноры/факультативы, Data Culture, магистратура и другие факультеты. **Не считать этот перечень исчерпывающим; фактическую структуру определять обходом**.

Контролируемые примеры:
- `https://disk.yandex.ru/d/lwE14jdmI4qZEQ`: публичная папка с несколькими направлениями; перечислять дерево и содержимое через документированный публичный интерфейс, когда доступен.
- `https://youtu.be/mROFPH8WKZg`: пример видеолекции «Основы и методология программирования, ПМИ основной поток — лекция 09.09.2021»; метаданные не равны просмотру видео.
- Оригинальные или зеркальные страницы `wiki.cs.hse.ru` могут помочь в атрибуции; не путать зеркало и исходник без проверки.

## 2. Политика по умолчанию
Пользователь сообщил, что **сайт предоставляет свободное использование коллекции кроме коммерческой деятельности**; его проект исключительно личный и некоммерческий. Принимаем это как **утверждённое пользователем рабочее условие**. Для открытых учебных объектов, найденных из Wiki и связанных курсов, автоматическая инвентаризация и личная обработка начинаются **без пофайлового запроса разрешения** и без требования увидеть фразу «разрешено для ИИ». Не конструировать искусственный блокирующий статус `rights_unknown`.

При доступности страницы с общей политикой можно сохранить её ссылку/текст **один раз**, не ставя всю работу на паузу. Нельзя без проверки утверждать, что универсальная лицензия сайта юридически охватывает каждого внешнего автора/платформу. Если появляется **конкретное** несовместимое условие, фиксировать источник, вид операции и альтернативы. Отдельно учитывать технические условия способов получения: публичное воспроизведение YouTube не идентично предоставленному API скачивания; не обходить логины, DRM, капчи или закрытый доступ.

## 3. Состояния отдельно по осям
- `discovery`: `found / enumerated / absent_after_check / not_checked`.
- `access`: `public / authentication_needed / not_found / rate_limited / platform_restricted / transient_error / unknown`.
- `content`: `metadata_only / retrieved / text_extracted / video_transcribed / content_analyzed / analysis_pending`.
- `verification`: `unreviewed / candidate / partial / verified / rejected / insufficient_evidence`.

Не «терять» источник после 403/404/429/502. Регистрировать попытки и альтернативные копии. Разделять неизвестные материалы и действительно подтверждённые пробелы.

## 4. Контролируемый обход
- `fruitdet.ru/wiki/*` — главный граф страниц; за пределами него — только учебные целевые ресурсы с явной ссылкой от первичного графа, без глобального обхода интернета.
- Исключить зацикливание, служебные спецстраницы, бесконечные параметры, страницы логина, поиск по всему домену, временные подписанные URL и неучебные рекламные ссылки; фиксировать причину исключения.
- Отдельные адаптеры: публичные облачные папки, конкретные репозитории, видео/плейлисты, сайты преподавателей, прямые документы/архивы.
- Осторожные интервалы запросов, backoff по 429/5xx, поддержка robots.txt и ограничения размера/числа вложений. Не запускать обнаруженные программы, изолировать извлечение архивов, проверять SHA-256.

## 5. YouTube и облака
Для видео сохранять `video_id`, платформу, канал, дату/название/плейлист, ссылку на курс, доступные пользовательские транскрипты и **отдельный статус** получения аудио/ASR/кадров. Если прямое извлечение недоступно допустимым способом, искать опубликованную автором копию, расшифровку, слайды и записи других годов; не закрывать задачу одной карточкой видео. Для Yandex Disk поддерживать `public_key`, `path`, пагинацию, родительские каталоги, целостность и неполные списки.

## 6. Что запрещено при любой политике
Автоматически публиковать чужие материалы, обходить закрытые аккаунты, извлекать секреты из репозиториев, запускать макросы/EXE и игнорировать нагрузку на сайты. Обработка идёт для личного локального образования.
