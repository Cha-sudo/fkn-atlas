# Предпочтительная архитектура, не жёсткий стек

## 1. Канонический конвейер
`Wiki seed → очередь URL → HTML + контекст ссылок → каталог ресурсов → адаптер провайдера → перечисление вложений → получение оригинала (когда доступно) → извлечение содержимого → индекс/эмбеддинги → кандидаты на сопоставление → проверка доказательств → объединённые курсы → интерфейс`.

Разделить уровни **сбора фактов** и **производных ИИ-гипотез**. Все переходы и ошибки логируются. Смена движка ASR/LLM не должна требовать повторного скачивания оригиналов.

## 2. Компоненты
- **Crawler**: ограниченная область, роботы, нормализация URL, очередь, паузы, retries, idempotency, checkpoint.
- **Provider adapters**: Wiki/HTML, Yandex Disk public, YouTube metadata/accessible transcript, Google Drive public, Git/GitHub, прямые файлы, архивы. У каждого `probe`, `list_children`, `fetch`, `extract`, capabilities и статусы.
- **Storage**: SQLite для прототипа; Content-Addressed blob store для оригиналов; отдельные производные тексты/ASR/кадры, JSONL экспорты. Схема подробнее в `DATA_MODEL.md`.
- **Course parser**: извлечение программы/потока/курса/года/темы из HTML, заголовков таблиц, даты, URL и окружающего текста. Сохранять сырой контекст и уверенность; поддержать ручную коррекцию.
- **Reconciler**: дедупликация файла по SHA-256 + поиск тематических кандидатов через метаданные/эмбеддинги + проверка покрытия. `RECONSTRUCTION.md`.
- **QA/Reports**: полный audit trail, неизвестные, непроверенное, частичные ошибки и метрики со знаменателями.
- **UI (позже)**: дерево программы/года/дисциплины, просмотр доступных источников и объединённого курса, открытые пробелы, карта взаимосвязей, личный учебный кабинет.

## 3. Разделение машинной и интеллектуальной работы
Детерминированные операции делаем без LLM. Локальный LLM доступен опционально через локальный API (Ollama/LM Studio); можно использовать embedding-модель для поиска близких фрагментов. Codex и субагенты пригодны для архитектуры, редких сложных случаев и аудита, но не для ручной обработки каждой из тысяч ссылок. `DELEGATION_AND_LOCAL_AI.md`.

## 4. Масштабирование
- `source_events` append-only / история проверок; отдельная очередь работ с этапами, retry/backoff.
- Байтовые лимиты, дисковые квоты, контроль глубины и конкретной папки/плейлиста; не делать обход по одному бесконечному рекурсивному запросу.
- Отделить независимые параллельные worker'ы от SQLite single-writer. На большой нагрузке — batched writes/один writer; PostgreSQL при необходимости.
- Проверка оригинала, хеша и структуры перед запуском длительных ASR; оригинальные видео не перезаписывать.
- Прогресс должен быть возобновляемым; UI не является обязательным условием начала массовой обработки.

## 5. Статус текущего кода
`src/fkn_atlas` — ограниченный Python scaffold: offline demo + разведка внутренних HTML-страниц, SQLite, provenance-ссылки, CSV/JSON не предусмотрены. Он намеренно **не выполняет** облачные загрузки, глубокий разбор PDF/видео, классификацию курсов и сопоставление. Codex должен оценить и расширить или заменить эту реализацию с тестами.
