# Архитектура и рабочий контракт

## Данные и границы доверия

Python + SQLite/FTS5, синхронный ограниченный HTTP-работник. `Store` хранит `objects/<sha-prefix>/<sha256>` неизменяемо, а производные — в `derived`. URL, SHA снимка, время попытки и результат извлечения разделены. Один URL может иметь несколько успешных снимков и множество неудачных попыток. SHA проверяется при повторной записи и командой `verify`.

В `resources` постоянный ID вычисляется из нормализованного URL. Фрагмент URL не входит в ID ресурса, но исходный href остаётся в `occurrences`. Домены зеркал не склеиваются с оригиналом. HTML сохраняется целиком; дерево `nodes` хранит родителей, порядок и DOM-путь, таблицы и вложенные списки. `occurrences` хранит каждое вхождение ссылки с контекстом, заголовками и отдельным ID. Контекст целиком остаётся приватным: страницы могут содержать персональные сведения.

`source_edges` связывает обнаруженный GitHub ref с закреплённым деревом API. Дерево порождает ссылки на raw-файлы с commit SHA. Ничего из найденных репозиториев не исполняется. Импорт ответа коннектора помечается как локальный импорт с исходным URL, а не выдуманный прямой HTTP-запрос.

Очередь `jobs`: pending → running → done/retry/blocked. Claim выполняется в транзакции, содержит токен и срок аренды. Просроченный работник не может завершить чужую задачу. Работа вне разрешённых доменов не выбирается из очереди. Ошибки 429/5xx повторяются с backoff; автоматический повтор ограничен. Четыре неудачи не означают исчезновение материала.

Сеть: allowlist хостов, HTTP(S), публичные DNS-адреса, проверка redirect, robots.txt, пауза между запросами, ограничение ответа и времени. В данной управляемой Windows-среде публичные домены резолвятся в DNS-прокси `198.18.0.0/15`. Только здесь испытано явное `ATLAS_BENCHMARK_DNS_PROXY=1`; оно допускает лишь эту сеть для уже разрешённых хостов. На обычном ПК оставляйте выключенным. Это локальное приложение, не интернет-сервис и не изоляционная песочница для враждебных документов; DNS-rebinding требует дополнительного сетевого периметра при будущем серверном развёртывании.

## Содержание и педагогика

`versions → lessons → lesson_materials` фиксирует программу, год, дисциплину, поток, порядок и источник утверждения. Сохранённый план ещё не подтверждает содержание. Состояния: `not_in_plan`, `listed_without_link`, `link_unavailable`, `obtained_unread`, `partial`, `unverified`, `content_checked`. Нельзя выводить `not_in_plan` из отсутствия найденной ссылки.

`extractions → chunks` хранит страницы, DOM-пути, ячейки notebook или временные интервалы субтитров. Каждая запись относится к конкретному SHA и версии извлекателя. PDF получает `needs_visual_review`; размер текста используется только как технический сигнал возможного отсутствия текстового слоя, никогда как оценка ценности.

`fragments → assessments` — выделенные рецензентом смысловые фрагменты и версии индивидуальных оценок. Программа не создаёт интеллектуальные заключения из длины, даты, формата или заголовка. У каждого фрагмента несколько точных якорей `chunk_id + quote`; ссылка, SHA и локатор восстанавливаются по цепочке. `annotate` отклоняет выдуманные цитаты и требует все поля:

```text
title, topic, subtopics, anchors:[{chunk_id,quote}], reviewer,
analysis:{functions,completeness,depth,correctness,clarity,sequence,
proofs,examples,illustrations,exercises,prerequisites,learning_outputs,
uniqueness,source_quality,limitations,confidence,check_method}
```

Образовательные функции: introduction, intuition, definition, theoretical_justification, proof, method_demonstration, application, worked_problems, common_errors, deepening, assessment. Функций может быть несколько. `prerequisites` и `learning_outputs` — списки стабильных понятий, `confidence` — high/medium/low/unknown; остальные измерения описываются текстом с границами проверки. Неизвестное пишется явно. Общего балла качества нет.

`compare` принимает два ID фрагментов, relation, dimensions, reason, limitations. Типы: полное/частичное замещение, более ясное объяснение в конкретном отношении, углубление теории, дополнительная практика, альтернативный подход, уникальное содержание, недостаточно данных, отклонение. Ссылки на версии индивидуальных оценок сохраняются в dimensions.assessment_refs.

`trajectory` принимает title, initial_knowledge, steps:[{fragment_id,reason,transition}], limitations. Проверяет, что предпосылки следующего шага уже заданы или приобретены; фиксирует конкретные версии оценок. Это производный выбор рецензента, оригиналы и альтернативы сохраняются.

`review` принимает lesson_id, verdict, covered, uncovered, reason, reviewer, evidence:[{chunk_id,quote,check_method,source_version_id}]. Покрытые и непокрытые темы должны точно разбивать объявленные подцели. Verdict: confirmed_scope/partial/unique_addition/rejected/insufficient_data. Рейтинг поиска не меняет эти состояния. Положительное решение требует точных цитат, но истинность математического суждения всё равно проверяет рецензент. Исходное состояние доступности занятия не переписывается решением о восполнении.

Восстановление по умолчанию ограничено той же программой и тем же курсом; различие года само по себе не препятствие, но совпадение темы не доказывает эквивалентность. Для каждого доказательства проверяется путь от версии курса до материала по графу происхождения. Замена из другой дисциплины/программы требует `transfer_authorization:{node_id,quote,reason}`: точной цитаты прямого указания в исходной странице целевого курса. Код проверяет принадлежность и цитату; рецензент обязан проверить, что это именно разрешение переноса. Без такого основания другой курс — только дополнительное чтение. `compare` допускает отношения замещения лишь при общей области курса; межкурсовое исключение оформляется через `review`, не через обход этого ограничения.

`plan` принимает `{version:{program,year,course,stream,source_snapshot,evidence_node},lessons:[{label,position,topics,status,evidence_node,notes}]}`. Узлы должны относиться к исходному снимку версии.

## Обработчики и следующие границы

PDF: pypdf + необязательный рендер PyMuPDF. HTML: BeautifulSoup, UTF-8 в испытанных MediaWiki. Остальные кодировки пока не определяются автоматически. Notebook читается без исполнения, VTT/SRT сохраняет интервалы; связь транскрипта с конкретным видео пока задаётся исследователем. ZIP/Office: только перечень членов без распаковки, размеры и подозрительные пути; Office-текст/OCR не реализованы.

Яндекс Диск: первая страница public resources API (до 100 элементов), без заявления полного рекурсивного обхода. YouTube: oEmbed, не субтитры или ASR. Dropbox: официальный параметр [dl=1](https://help.dropbox.com/share/force-download), если robots и доступ разрешают. Реальный пилот Dropbox остановлен robots.txt. GitHub: импорт дерева API, ссылки на закреплённые raw-материалы. Google Drive и GitLab: обнаружение/классификация и локальный импорт.

Следующая итерация должна расширять реальное содержание: задачи по Гауссу, ещё один поток/программа, затем новые предметы. До массового сбора нужны отдельная очередь извлечения с процессными лимитами, ручные состояния семантической проверки, пагинация провайдеров, миграции схемы и резервирование на второй носитель. Локальный ИИ не является текущим направлением.
