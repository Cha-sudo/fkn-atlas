# Потоковое получение оригиналов: итерация 1.2

16 ноября 2026 года. Существующая очередь jobs и граф происхождения сохранены. Межкурсовые ограничения не ослаблены. Присутствие файла в библиотеке не означает, что его содержание изучено.

## Что реализовано и проверено

HTTP-ответы пишутся блоками по 64 KiB в приватный `partials/*.part`. Таблица transfers хранит подтверждённую длину, SHA-256 префикса, сильный ETag, Last-Modified, полный размер, конечный URL и состояние. Блок fsync-записывается до фиксации checkpoint SQLite. Токен аренды проверяется в той же транзакции; просроченный работник не может дописать файл другого работника. После сбоя лишний хвост за последним checkpoint отбрасывается с записью события. Повреждённый префикс не используется.

Возобновление отправляет Range и If-Range только при сильном ETag. Принимается 206 с точным начальным смещением, согласованными Content-Length/Content-Range, тем же ETag, полным размером и конечным URL. Кодирование HTTP должно быть identity. При 200 старый неполный префикс сбрасывается, ответ сохраняется с нуля. При 416 выполняется ограниченный повтор с нуля; сам 416 не доказывает полноту файла. Без сильного ETag, в том числе только с Last-Modified, выполняется повтор с нуля. Last-Modified сохраняется для диагностики, но не считается достаточным сильным валидатором. [Основание: HTTP Semantics, Range и If-Range](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.5).

Только после нормального окончания ответа, проверки длины, повторного потокового SHA-256 и fsync файл атомарно переносится в objects и регистрируется как snapshot. Сбой после rename до commit восстанавливается из объекта с ожидаемым SHA без повторной загрузки. Дедупликация сохраняет разные источники и один объект одинаковых байтов. SHA доказывает целостность сохранения, не истинность содержания и не авторство. Старые успешные снимки остаются неизменными; причины сброса неполных байтов сохраняются в transfer_events.

По умолчанию: файл до 1 GiB, порция до 128 MiB, 300 секунд, 20 GiB суммарно для объектов и .part, резерв свободного места 1 GiB. Все эти ограничения настраиваются. Сетевой буфер может получить сверх остатка бюджета один блок, но лишний суффикс не фиксируется в checkpoint. Метаданные/SQLite/производные не входят в квоту исходных байтов; свободное место проверяется отдельно. Порог времени относится к сети и проверке SHA; тяжёлые парсеры документов пока не имеют процессной изоляции.

Видео/аудио распознаются по MIME, сигнатуре/расширению до полного чтения: сохраняется media_untranscribed без `read_bytes()` всего оригинала. Документы больше 32 MiB откладываются для отдельного извлечения; большие ZIP получают archive_stored_unread. Автоматической распаковки, исполнения макросов, ASR/OCR нет. Локальный импорт также копирует и хеширует потоково; предел 32 GiB на файл и квота исходников 20 GiB, существующий объект повторно не копируется. Прерывание локального копирования пока не возобновляется по checkpoint; оставшийся staging сохраняется.

**54 теста прошли локально.** Добавлены сценарии обрывов, слабого/отсутствующего/изменившегося ETag, ошибочных диапазонов и длин, ответов 200/206/416, изменения redirect-цели, ограниченных сегментов, неизвестной полной длины, времени/байтов/места, порчи checkpoint, хвоста после сбоя, stale worker, дедупликации и сбоя фиксации объекта. Отдельный тест использует настоящий локальный HTTP-сервер и корректный созданный WAV длиной 3 секунды (264 644 байта): разрыв после 65 536 байт, затем Range-resume и точное совпадение SHA. Это синтетический сигнал, **не полученная учебная аудиозапись**. Проверено отсутствие whole-file read для двух файлов больше 32 MiB. Многогигабайтное видео специально не скачивалось; потоковая архитектура и границы памяти проверены на ограниченных данных.

## Реальный Google Drive и содержательная проверка

Через уже подключённый Google Drive, без нового входа и установок, прочитаны метаданные и получен оригинальный [учебный PDF](https://drive.google.com/file/d/1SX2LXXiooxpgBasL3BFDQ3x4gOSYGpD-/view), прямо связанный со страницей ПМИ 2024/25: `LA_24-25_Sheet1.pdf`, 123 922 байта, SHA-256 `8623f34eabfa84bc62ec04699787cae60edb3ccb216347765b3fb3194d8c9975`. Коннектор вернул полный файл, который импортирован с исходным URL. Временная служебная ссылка получения не включена в Git. Это подтверждает доступ через данное подключение, не анонимную общедоступность и не автономность CLI.

Прямой анонимный запрос официального Drive v3 files.get после проверки robots получил HTTP 403 PERMISSION_DENIED/ACCESS_DENIED. Это точный результат данной среды, не доказательство отсутствия файла. Родительские ID коннектор не предоставил; в сохранённой выборке не обнаружено идентифицированной ссылки на Drive-папку. Папки целиком не проверены. Доступные folder-инструменты ограничивают выборку прямых детей; по одной странице нельзя объявлять полный рекурсивный обход. [Официальные варианты скачивания](https://developers.google.com/workspace/drive/api/guides/manage-downloads), [ссылки с resourceKey](https://developers.google.com/workspace/drive/api/guides/resource-keys). Автономного Drive-адаптера без предоставленного API-доступа в CLI пока нет; поддержанный минимум — коннектор → оригинал → локальный импорт, либо файл, предоставленный пользователем.

Визуальная проверка показала, что «Листок 1» посвящён **матричным алгебрам Ли**, а не практике по Гауссу. Кириллица текстового слоя повреждена отображением шрифта; оригинал не переписывался. Восьмой индивидуально оценённый фрагмент ограничен определениями коммутатора/матричной алгебры Ли и задачей 1. Тождество Якоби проверено независимым раскрытием и сокращением некоммутативных слов. Образовательные функции — определение и проверка знаний; готового доказательства в этом фрагменте нет. Задачи 2–8 и весь листок не объявлены верифицированными. Отдельного внешнего рецензента не было.

В приватной библиотеке теперь **112 оригинальных объектов и 8 оценённых фрагментов**. Добавлен ровно один новый учебный файл в этой порции. Полных/частичных восстановлений исторических занятий остаётся **0**; решение по ПМИ → КНАД остаётся rejected. Новая привязка листка создана только к проверенной версии ПМИ; упоминание ЭАД в заглавии само по себе не создало версию, траекторию или замещение другого курса.

## Возобновление на Windows

```powershell
.venv/Scripts/python.exe -X utf8 -m atlas transfers
.venv/Scripts/python.exe -X utf8 -m atlas resume RESOURCE_ID
.venv/Scripts/python.exe -X utf8 -m atlas run --allow SOURCE_HOST --budget 2 --max-file-mib 4096 --max-total-mib 128 --max-storage-gib 20 --reserve-free-mib 1024 --seconds 180
```

Команды с RESOURCE_ID/SOURCE_HOST — шаблоны: возьмите их из transfers. Для crawl действуют те же сетевые квоты, а scope продолжает контролировать переходы. Остановка по порционному бюджету оставляет pending, её достаточно продолжить той же командой. `resume` возвращает retry/deferred в очередь без сброса .part; для смены файла с нуля есть явный `seed --refresh URL`. Запреты robots, закрытый доступ и неизвестные внешние redirect не обходятся. Signed URL, поменявшийся URL и сервер без сильного валидатора могут потребовать повтор с нуля; склеивания по одному имени файла нет.

Приватные квитанции: `drive-read-receipt.json`, `drive-anonymous-probe.json`, `annotation-8.json`, `drive-fragment-check.json`, `derived/drive-sheet1-page1.png`. Следующий практический шаг — обнаружить конкретную учебную Drive-папку из Wiki и проверить реальное постраничное перечисление при доступном подключении, либо продолжить другую разрешённую ветвь с файлами. Не выдавать проверенную транспортную фикстуру за просмотр учебного видео.
